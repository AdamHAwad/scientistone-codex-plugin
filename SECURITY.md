# Security policy

## Supported versions

Security fixes cover the latest released minor version. Pre-release builds receive best-effort support.

## Report a vulnerability

Do not open a public issue for an unpatched flaw. Do not put secrets, private research data, or exploit data in a public report. Use GitHub private vulnerability reporting for this repository. If that option is missing, open a public issue that asks only for a private contact channel.

Include the affected version, component, impact, reproduction conditions, and a small non-sensitive example. Maintainers will confirm a valid private report as soon as practical and plan disclosure after a fix.

## Scope

Useful reports include path-boundary failures, evaluator-only data leaks, command injection, unsafe archive handling, MCP protocol or origin flaws, content security policy bypasses, hidden network requests, secret exposure, dependency compromise, and package-content errors.

Research disagreements and reproducibility failures belong in normal issues unless they also create a security problem.
